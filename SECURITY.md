## Reporting a vulnerability

Please do **not** report vulnerabilities through public GitHub issues.

1. Email **hi@aiianer.de** with the subject `[SECURITY] hermes-gmail-guard`.
2. Describe the issue as precisely as possible: affected component, steps to reproduce, possible impact.
3. You'll get a first response within **72 hours**.

**Especially relevant for this project:** anything that lets the agent **send mail**,
bypass the **approval fingerprint** or the **bulk brake**, approve as someone other
than the owner, reach the **token files**, or touch the owner's own drafts.
Please report findings in these areas with top priority.

**We commit to:** confirming receipt and keeping you updated, fixing confirmed
issues with priority, crediting you in the release notes if you wish, and no legal
action against good-faith security research (responsible disclosure).

**Please don't:** publish the issue before a fix is released, access third-party
data, or test systems beyond what's necessary.

### Eine Sicherheitslücke melden

Bitte melde Sicherheitslücken **nicht** über öffentliche GitHub-Issues.

1. Schreib eine E-Mail an **hi@aiianer.de** mit dem Betreff `[SECURITY] hermes-gmail-guard`.
2. Beschreibe die Lücke so konkret wie möglich: betroffene Komponente, Schritte zur Reproduktion, mögliche Auswirkung.
3. Du bekommst innerhalb von **72 Stunden** eine erste Antwort.

**Besonders relevant bei diesem Projekt:** alles, womit der Agent **Mails senden**,
den **Freigabe-Fingerabdruck** oder die **Masse-Bremse** umgehen, sich als jemand
anderes als der Besitzer freigeben, an die **Token-Dateien** kommen oder die eigenen
Entwürfe des Besitzers anfassen kann. Funde in diesen Bereichen bitte mit höchster
Priorität melden.

**Was wir zusagen:** Eingangsbestätigung und Updates, priorisierte Behebung
bestätigter Funde, Nennung in den Release Notes (wenn gewünscht), keine rechtlichen
Schritte gegen Sicherheitsforschung in gutem Glauben (Responsible Disclosure).

**Bitte nicht:** die Lücke veröffentlichen, bevor ein Fix draußen ist, Daten Dritter
abgreifen oder Systeme über das Nötigste hinaus testen.
